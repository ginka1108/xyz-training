# XYZトレーニング

一向聴の手牌に、聴牌する牌 **X** をツモった状態を出題し、
制限時間内に切る牌 **Y** と待ち **Z** を答える麻雀トレーニング。

## 遊び方
1. 右端のツモ牌 X を確認する
2. 手牌から切る牌 Y をタップ（聴牌になる切り方ならどれでも正解）
3. 待ち Z をすべて選んで「決定」（切った牌に対応する待ちと完全一致で正解）

## 採点（初期値、画面の設定で変更可）
- 正解で100点から、減点なしの時間を過ぎると1秒ごとに減点。最低10点。
- Y：5秒まで減点なし、以降 −5点/秒、制限15秒
- Z：「3秒 ＋ 3秒 × 待ちの種類数」まで減点なし、以降 −3点/秒、制限40秒
- 不正解・時間切れは0点

## 問題の作り方
- 和了形を作り、1〜2枚抜いて手牌とつながる牌を足し、一向聴になったものを使う。面子を同じ色の近くに寄せて複合形を増やしている。
- 浮き牌を切るだけの易しい問題は全体の5〜7%程度に抑えている。
- 萬・筒・索や字牌の種類を入れ替えただけの問題は「同じ形」とみなし、直近3000件はその端末で再出題しない（ブラウザに保存）。
- `node scripts/variety.js` で、重複率・易しい問題の割合・待ちの種類数の分布を確認できる。

## 二向聴モード
- 二向聴の13枚に、一向聴に進むツモ X。Y は一向聴を保つ切り方ならどれでも正解（設定で「受け入れ最大のみ」に切り替え可）。
- Z は切った後に聴牌へ進む牌（受け入れ）すべて。部分点あり：`(当たり − 余計) ÷ 正解数` を時間点に掛ける。
- 初期値：Y 8秒まで減点なし・制限25秒、Z「5秒 ＋ 2秒 × 種類数」まで減点なし・制限60秒。
- 連続設問（二向聴）：同じ13枚で X ごとに「受け入れ最大の切り方」が1通りに決まり、かつ X ごとに違うものを3〜5問。このモードは常に受け入れ最大のみ正解（`generateTwoShantenSeries`）。
- シャンテン数は `Mahjong.shanten()`（通常形のみ）。同じ牌を4枚持つ手は出題しない（空聴の扱いを避けるため）。

## 今日の10問
- 日本時間の日付をシードにして、聴牌版のランダム問題を10問作る（`Mahjong.generateDailySet(date)`）。同じ日なら誰でも同じ問題。
- 乱数は `mulberry32`、シード文字列は `xyz-daily-v1|YYYY-MM-DD`。問題の作り方を変えたら `DAILY_VERSION` を上げる（変えないと同じ日付でも問題が変わってしまう）。
- 設定を変えていても、採点は初期値で行う。
- 記録はブラウザに日付ごとに保存（初回の点・ベスト・回数）。結果画面の「結果をコピー」で `○○△×…` 付きの文字列をコピーできる。
- サーバーで採点し直すときは、同じ `mahjong.js` で `generateDailySet(date)` を呼べば同じ問題が得られる。

## ランクチャレンジとランキング
- 4モード×10問（計40問・4000点満点）。設定は初期値で固定。
- 問題は「パック」（1モード10問）単位。`scripts/build-site.js` がビルド時に各モード500個を `site/packs/v1/<モード>/<番号>.json` に作る。開始時にサーバーが各モードのパック番号を選ぶ。
  - サーバー（Cloudflare の無料プラン）は1回 10ms しか計算できないため、その場で問題を作らない。
  - 問題の作り方を変えたら `CHALLENGE_VERSION` を上げる。
- ブラウザは答えと時間だけを送り、サーバーが `Mahjong.gradeQuestion` で採点し直す。同じ挑戦は1回だけ、開始から60分以内、申告時間の合計が実際の経過時間を超えたら受け付けない。人間に無理な速さの答えがあればランキングから外す。
- 名前は端末ごとの合言葉（ブラウザに保存）に結び付く。表記ゆれ（カタカナ/ひらがな・大文字/小文字）は同じ名前扱いで、重複不可。禁止語はシャドウ（本人以外には「名無しさん」）。`server/names.mjs`
- 成績証明書：`/c/<記録ID>` の公開ページ（X に貼るとカードが出る）。表示は `js/cert.js` を画面とサーバーで共用。
- サーバー：`functions/`（Cloudflare Pages Functions）と `server/`。データベースは D1（`DB`）。設定手順は `docs/hosting.md` の 7.
- 手元での確認：`node scripts/build-site.js` の後、`npx wrangler pages dev site --d1 DB --binding ADMIN_KEY=test`
